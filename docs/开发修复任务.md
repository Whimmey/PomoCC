# PomoCC 开发修复任务清单

## 目标

修复当前版本中会影响监督准确性、发信安全性、界面响应和数据可靠性的关键问题。

执行顺序按依赖和风险排列。除非任务明确要求，不要顺手重构无关 UI 或修改产品行为。

## 执行原则

- 先建立或补充测试，再修改实现。
- 监督逻辑不能依赖 WinForms UI 线程是否响应。
- 进程实例按 PID 和启动时间识别，规则仍按 exe 汇总判断。
- 后台线程不得直接操作 WinForms 控件。
- 发信前在协议边界重新校验输入，不能只依赖设置界面校验。
- 配置迁移失败时必须可重试，不能因为部分文件存在就认为迁移完成。

## 第 0 组：建立基线与测试入口

### 目的

在大改核心逻辑前，确认当前版本的构建和既有自检结果，避免修复过程中无法区分新旧问题。

### 任务

- 确认 `build.ps1` 可以从干净源码构建。
- 确认 `--selftest`、`--smoketest`、`--dpicheck`、`--rendertest` 的运行方式。
- 在 `SelfTest.cs` 中补充本次修复需要的测试入口和测试数据构造方法。
- 不要求当前所有新增测试一开始就通过；先记录基线结果。

### 验收标准

- 能明确得到构建结果和每个自检命令的退出码。
- 测试使用临时数据目录，不写入用户真实配置、历史记录或生产注册表项。

## 第 1 组：监督核心重构（最高优先级）

涉及文件：`Supervisor.cs`、`Monitor.cs`、必要时新增时钟或后台监督类。

这一组必须作为一个整体设计，不能分别用局部补丁解决。

### 1.1 后台计时，不依赖 UI Timer

- UI 的 `System.Windows.Forms.Timer` 只负责刷新界面。
- 监督核心使用后台循环或 `System.Threading.Timer`。
- 使用 `Stopwatch` 或其他单调时钟计算真实经过时间。
- 普通 UI 卡顿期间，专注时间仍然继续计算。
- 监督线程负责计时、进程采样、规则判定和状态变化。
- UI 通过状态快照读取数据，并使用 `BeginInvoke` 更新控件。

### 1.2 正确处理睡眠和休眠

- 监听 Windows 电源状态变化。
- 系统进入睡眠/休眠时暂停本段计时。
- 系统恢复时重置计时基准，不能把睡眠期间的时间加入专注时间。
- 对无法判断的超长时间间隔使用保守处理，并写入事件日志。

### 1.3 进程按实例识别，按 exe 汇总

- 单个进程实例的身份至少包含 `Exe + PID + StartTime`。
- 每次采样，一个实例只能累计一次采样间隔。
- 进程退出后再次启动，即使 exe 相同，也必须视为新实例。
- PID 复用时，必须通过启动时间避免误认为同一个实例。
- 规则判断仍按 exe 汇总总运行时间，而不是为每个 PID 单独套一份规则。
- 邮件和界面可以显示 exe 总时间，并可附带实例数量。

### 1.4 明确专注结果状态

不要继续用 `Reported` 一个 bool 同时表达“已经发过邮件”和“最终结果”。引入明确的结果状态，例如：

```text
Running
Completed
Abandoned
Violated
```

规则建议：

- 正常走完且没有违规：记为 `Completed`，触发完成提醒。
- 中途放弃且没有违规：记为 `Abandoned`，发送一次告状。
- 程序超时：记为 `Violated`，发送一次告状。
- 已经违规后用户继续坚持到结束：仍记为 `Violated`，不能再显示“未告状”，也不能再次发信。
- 已经违规后再点击放弃：不重复发信。

### 1.5 线程安全

- `StartFocus`、`Abandon`、`Complete`、设置应用、后台 Tick 必须通过统一同步机制保护。
- 不要让 UI 直接修改后台线程正在使用的 `Session`、`Stats`、`Settings` 集合。
- 设置应用时为当前 session 固定配置快照，避免后台任务读到一半更新的配置。
- 事件回调不要在内部锁未释放时执行，避免 UI 回调造成死锁。

### 本组验收标准

- UI 线程阻塞 5～10 秒时，专注时间不会停止或少算。
- 系统睡眠 1 分钟后恢复，睡眠时间不计入专注。
- 同一个 exe 同时运行多个进程时，每次采样不会重复累加。
- 同一个 exe 退出后重新启动，累计时间连续但实例身份正确。
- 已违规后完成或放弃，不会重复发送邮件，也不会被记录为“正常完成且未告状”。
- 现有状态机和邮件正文测试继续通过。

## 第 2 组：发信安全边界

涉及文件：`Settings.cs`、`SettingsForm.cs`、`HttpSender.cs`、`SmtpTransport.cs`。

### 2.1 自定义 HTTP 地址限制

- 固定的 Resend、SendGrid、Brevo 地址保持 HTTPS。
- 自定义接口必须是绝对 URL。
- 允许 `https://`。
- 仅对本机服务例外允许 `http://localhost`、`http://127.0.0.1`、`http://[::1]`。
- 拒绝其他明文 HTTP 地址。
- 拒绝 URL 中携带用户名、密码或 API Key 的写法。
- API Key 继续放在请求头，不放在查询参数中。

### 2.2 SMTP 邮箱和协议字段校验

- 发件人和收件人必须拒绝 `\r`、`\n`。
- 使用 `MailAddress` 或等价的严格校验，而不是只检查 `@`。
- SMTP 命令中的邮箱地址不能允许额外命令注入。
- 邮件 `From`、`To` 头部使用同一套校验结果。
- 对主题、正文继续保持现有的编码方式。

### 本组验收标准

- `http://evil.example` 被拒绝。
- `http://localhost:xxxx` 可以使用。
- `https://example.com` 可以使用。
- 含有换行的发件人或收件人无法保存，也无法通过直接调用发送入口发送。
- Resend、SendGrid、Brevo 的请求格式和认证方式不改变。
- 假 SMTP 测试仍然可以完整完成 EHLO、认证、DATA 和结束流程。

## 第 3 组：手动发信异步化

涉及文件：`SettingsForm.cs`、`Dialogs.cs`、`MainForm.cs`，必要时新增统一的异步发送辅助类。

### 任务

- SMTP 连接测试放到后台线程。
- 测试发信放到后台线程。
- 历史记录重发放到后台线程。
- 自动告状发送继续保持后台执行。
- 请求期间禁用相关按钮，显示“测试中/发送中”。
- 完成后通过 `BeginInvoke` 回到 UI 线程显示结果。
- 窗口关闭后忽略已经返回的旧结果，避免访问已释放控件。
- 给 SMTP 建立连接设置明确的连接超时；`ReceiveTimeout` 不能代替连接超时。

### 验收标准

- 网络不可达或服务器超时时，窗口仍可拖动、关闭和切换页面。
- 同一个测试按钮不能在一次请求结束前重复点击。
- 成功和失败都能恢复按钮状态。
- 关闭窗口后，后台任务不会抛出跨线程控件异常。

## 第 4 组：持久化和迁移可靠性

涉及文件：`Store.cs`，必要时涉及 `Supervisor.cs` 的历史写入调用。

### 4.1 配置目录迁移

- 不要仅根据新目录中是否存在 `config.json` 判断迁移完成。
- 使用临时迁移目录或迁移标记。
- 先复制全部文件，再验证配置可以反序列化。
- 只有全部复制和验证成功后，才写入迁移完成标记。
- 迁移中断后，下一次启动必须可以继续迁移。
- 新目录已有用户文件时不能盲目覆盖。
- 确认新目录可用后，再删除或延迟删除旧目录。

### 4.2 历史记录并发写入

- `AppendHistory` 使用进程内写锁，避免多个后台发送同时交错写入 JSONL。
- 读取历史时跳过损坏行的行为可以保留，但要记录被跳过的行数或日志。
- 暂不要求本轮实现历史文件压缩或流式读取；历史文件大小问题列为低优先级后续优化。

### 验收标准

- 迁移复制任意一个文件失败后，下一次启动能够重试，不会因 `config.json` 已存在而永久跳过。
- 两个并发发送完成后，历史文件中仍然是两条完整 JSON 行。
- 迁移失败不会删除旧目录。

## 第 5 组：回归测试与发布验证

### 必须新增或补充的测试

- 多个相同 exe 进程不会重复累计。
- exe 退出后重新启动会生成新的实例身份。
- UI/监督 Tick 延迟时，普通卡顿时间会计入。
- 睡眠/恢复时间不会计入。
- 已违规后完成不会变成正常完成。
- 已违规后放弃不会重复告状。
- 自定义 HTTP 明文地址被拒绝，本机 HTTP 被允许。
- SMTP 邮箱中的 CRLF 被拒绝。
- 并发历史写入不会产生交错 JSON。
- 迁移中途失败后可以继续迁移。

### 发布前执行

```powershell
pwsh -File .\build.ps1
.\dist\PomoCC-番茄钟监督.exe --selftest .\tests\selftest.log
.\dist\PomoCC-番茄钟监督.exe --smoketest .\tests\smoketest.log
.\dist\PomoCC-番茄钟监督.exe --dpicheck .\tests\dpicheck.log
.\dist\PomoCC-番茄钟监督.exe --rendertest .\tests\rendertest.log
```

重点检查：

- 所有新增测试退出码为 0；
- 没有真实用户数据被改写；
- 没有遗留临时目录；
- 没有遗留测试用注册表项；
- UI 冒烟测试和 DPI 检查继续通过。

## 不纳入本轮

- 默认密码 `123456`：按当前产品决策保留。
- 旧版 `PomodoroSupervisor` 注册表值清理：只在开发阶段使用过，暂不处理。
- 历史文件整体压缩、归档和流式读取：当前不是阻塞问题。
- 与上述问题无关的视觉重构、命名调整和功能扩展。
